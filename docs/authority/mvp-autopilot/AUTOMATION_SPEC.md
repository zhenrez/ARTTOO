# ARTTOO MVP Autopilot — Automation Contract

## Driver
**Cadence:** hourly at :00.

Every run:
1. Read `docs/authority/AUTHORITY.md`.
2. Read `docs/authority/mvp-autopilot/STATE.md`.
3. Inspect current repo/branch/PR/CI state.
4. Identify the open MVP gate and single highest-leverage bottleneck.
5. Answer: verified state; open gate; bottleneck; critical-path relevance; closing evidence; smallest reversible implementation; $0 route; duplicate-state/provider-lock-in risk; reusable-component opportunity; owner-authority boundary.
6. Execute one authorized critical-path increment.
7. Verify with real tests/evidence.
8. Update `STATE.md` with exact continuation prompt.

## Governor
**Cadence:** every 4 hours at :30.

Every run:
1. Read `AUTHORITY.md` and `STATE.md`.
2. Compare actual repo evidence with claimed progress.
3. Classify `NORMAL`, `ELEVATED`, or `CRISIS`.
4. Audit critical-path alignment, scope drift, duplicate truth, adapter leakage, weak tests, avoidable cost, security/privacy/rights/payment/migration risk, unnecessary human attention, and bounded innovation opportunities.
5. Issue a concrete next-cycle directive and make only narrow safe process/test/state corrections.

## Owner-reserved boundaries
Agents must not autonomously spend money, accept legal/commercial terms, authorize real payments, delete user data, weaken security/privacy/rights controls, redefine MVP scope, or claim unverified accuracy/health outcomes. Consequential production deployment follows explicit release authority.

## Completion gate
MVP requires checkpoints 0–4, the full golden journey in one project lineage, save/reopen and failure recovery, revision-specific approval/export lineage, and no known release-blocking regression. On independent confirmation: produce final evidence report and disable Driver + Governor.
